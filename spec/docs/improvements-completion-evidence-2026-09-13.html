改善実装の追加証拠と切替条件（2026-09-13）

対象計画は改善実装計画。本書は実装済みの範囲と未充足の受入条件を区別する。先行作業の結果は初回証拠を参照する。

push後のCI失敗と、ユーザー指示による対象の見直し後の作業はCI・テストを除く残項目の修正を参照。本書のローカル検証記録はGitHub CIの成功を意味しない。

秘密ストア

macOS Keychain adapter、認証付き常駐IPC、TS設定保存・読出し・移行、Rust compile/queue/agent-sessionのリクエスト直前の参照解決を実装した。Writer内のKeychainアクセスは拒否する。秘密値を保存する前に新世代をjournalへ記録し、読出し検証後のCASで参照を切り替える。clearは無効状態を保存し、参照失敗・破損rowで環境変数へ暗黙に戻さない。

合成秘密を用い、実際のTS clientから常駐プロセスへ保存、旧平文移行、再起動、Keychain読出し、削除、backup内のバイト検査、別復元先のprofile拒否を検証した。既存のoffline backupはWriter lock取得後にcheckpointとVACUUM INTOを行うため、旧freelistの秘密をbackupへ複製しない。実機検証はmacOS arm64であり、他OSは環境変数運用のみ。利用者の実DBは変更していない。

複数キー更新はキー単位で確定する。一括transactionではない。回収journalには1時間の待機期限を置き、移行再実行で未参照世代を回収する。期限内の更新中世代は削除しない。削除済み旧世代を古いbackupから復活させない。手順は秘密値の保存と移行に記載した。

CI・依存境界・導入動線

SQLite専用テストは9ファイルをmanifestで管理し、別Bunプロセス・隔離DBで実行する。新規Bunテストの登録漏れは失敗となる。API配下のgraph/knowledge管理repositoryをsrc共有層へ移し、API側は再公開とHTTP処理に限定した。TypeScript resolverによるsrc→api検査、type-onlyとruntimeの区別、新規循環edgeの検査をverify:fastへ追加した。既存runtime循環はedgeごとに記録し、増加を拒否する。

onboardingは公開APIによるwiki source登録、知識のsource参照、compile、公開MCPでのeval保存、再起動後のsource/run/eval読出しへ拡張した。公開手順のcommand・goal・facetを共有fixtureで照合する。provider呼出しは0回で、Writer停止・readiness復旧・backup復元も維持する。

Bun/Cargo更新と週次監査workflowを実装した。Cargo監査は検出なし。Bun監査は120秒以内に応答せず監査不能として失敗した。重大検出・空report・timeout・期限切れ例外が成功へ変換されないことをfixtureで検証する。GitHubではsecret scanningとpush protectionが有効、Dependabot security updatesは無効、CodeQL default setupは未設定だった。analysis APIは権限不足を含む404のため過去実行を断定しない。新workflowの定期実行履歴・通知はdefault branchへの反映後に確認する。手順は依存監視にまとめた。

coverageの測定面

Vitestの実装対象をsrc/API/webへ広げた。型宣言（.d.ts）、テストソース、migration生成物のみを除外する。.types.tsにもschema・関数・classがあるためファイル名だけで除外しない。初期測定からこの分母を拡張した。Bun nativeはmanifest各ファイルのLCOVを行番号単位で結合し、Rustはllvm-covで別計測する。各runtimeの分母が違うため合算平均は製品coverageとして表示しない。PR baseとの差分から、runtime別の変更行coverageもreport-onlyで出す。削除行は分母に含めず、未計測行を成功扱いしない。Rust値にはinline unit testが含まれる点に注意する。

検索性能とcompile統一の判定

source参照を候補制限後に最大256件ごとの一括取得へ変更した。1万件から256件を保持するfixtureでsource queryは1回となり、既存順序・上限5件・snapshot整合性・多数bind・空候補の回帰試験を通した。1千/1万件、参照0/8件、日本語・短語・長goalの21反復fixtureを追加した。

初回の競合した計測は採用せず、旧版ff77032と修正版を同じprocessで交互に21回測定した。12条件すべてで完全な結果JSONが一致し、11条件でp95が改善した。1千件・参照0件・長goalは初回274ms→481msと悪化し、再測定693ms→579msで改善したが、ばらつきが大きいため両方を残した。1万件・参照8件・日本語ではp95が2,392msから488ms、長goalでは3,670msから1,778msだった。source queryは1万回から1回となった。対比較JSONに全条件と計測方法を記録した。製品環境のlatency保証ではなく、FTS候補削減の昇格は既存v2のrecall・isolation gateに従う。

最初の比較で見つかったmarkdownの差は、SQLiteのTS入口を現在のRust engineへ接続することで解消した。CLI・API/UI・init-projectは認証付き内部endpointを利用し、Rustがrunとsnapshotを一度だけ保存する。Postgresと明示securityIntelligenceShadowだけはlegacy互換経路を残し、通信失敗で旧engineへfallbackしない。共通JSON fixtureとZod、Rust unit tests、公開導線でDTO・source/session・DB binding・version・Origin/auth・128 byte相当の保守的予算・停止時503を検証した。

切替後の比較JSONで空結果・知識ありの採用ID、実source refs、No Content、markdownが一致した。現在のresident検索方式を共通化した範囲の受入であり、新しいv2 rankerやFTSの昇格を承認するものではない。出力予算による縮約ではcomposerの採用済み根拠だけを使い、不採用候補を戻さない回帰テストを追加した。未対応の旧引数は明示エラーとし、init-projectはpartial/degradedで成功判定しない。公開互換手順を参照。

配布候補

旧版ff77032をgit archiveから別directoryへbuildし、合成DBを候補版で開いて知識・run・evalの維持と追加compileを検証した。更新前backupを候補版で復元し、同じ知識・run・evalを確認した。旧版へ秘密参照を渡す復旧は許可しない。更新・復旧JSONに両binaryのchecksumを残す。

package/Cargoの0.1.0一致、schema revision 8、tag v0.1.0の検査、frozen install、web/Rust release build、noteとchecksum生成をmacOS arm64で実行した。最終配布候補manifestのSHA-256と実ファイルを照合した。dry-run workflowはcontents:readのみで公開しない。manifestはreleaseEligible:falseとし、署名・起動identityの受入が揃うまで配布可能と判定しない。手順は配布候補と更新に記載した。

最終検証と残る公開条件

verify:fast、verify:sqlite、verify:rust-daemon、verify:onboarding、verify:compile-parity、verify:secrets、ブラウザ4件、旧版からの更新/復旧、配布dry-runを実行した。Rustの最終測定は507件成功・5件ignoreで、ignoreされた性能matrixとmacOS Keychain受入は個別に実行した。Bunは9ファイル88件が成功した。利用者の実DBへ秘密移行を適用していない。

Rust運用gateは隔離profileと空のログ入力先で実行した。親環境からqueue無効設定を継承した初回smokeは意図した状態と異なり、環境を修正して再検証した。全並列Rust testでは既存recall性能試験が一度失敗し、test threadsを2に固定した最終実行で成功した。閾値は緩和していない。

Bun依存監査は2回とも120秒でtimeoutした。監査不能を成功とは扱わず、Cargo監査の検出なしと区別する。新規GitHub workflowの実行履歴・通知、署名済み配布物と自動起動identityの確認は公開前の条件として残る。Release公開・GitHub設定変更は実施していない。FTS/new rankerの昇格と実タスクA/Bは本計画の必須工程に含めない。
