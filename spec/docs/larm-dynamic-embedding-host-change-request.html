1. 依頼内容

  1. Embedding workerをLARMの動的host inventoryとadmission対象へ追加する。
  2. Embedding用途だけで取得・更新・解放できる短期lease／claim contractを提供する。
  3. claim結果からendpoint、短期credential、model identity、revision、dimension、正規化、prefix規則を検証できるようにする。
  4. queryとpassageを区別できる汎用Embedding protocolを提供する。
  5. 既存のService Activity、他service優先、fail closed、credential非永続化の方針を維持する。

2. 背景と影響

ContextStillのfinalizeDistilleは、ナレッジ本体を保存する前にEmbeddingを必須生成する。 現在の設定はhttp://127.0.0.1:44512/embedへ固定されているが、daemonが停止し、 2026-09-06から2026-09-09にかけて登録可能な19件が各5回失敗した。

  • 共通error: embedding daemon request failed
  • 95回claim、76回retry、19回terminal failed
  • coveringまでは全件knowledge_ready
  • 既存knowledge vectorは384次元が8,006件

ContextStill側でも停止時にjobを失わない修正を行うが、固定host停止という単一障害点を解消するには、 LARMの動的host選択をEmbeddingへ拡張する必要がある。

3. 必須contract

endpoint名や既存Agent Connection contractの拡張方法はLARM側の設計判断に委ねる。 ただし、ContextStillがclaim前後に次の情報を機械検証できることを必須とする。

LARMの動的Embedding claimで公開・保証する情報
field／能力 要件 理由
workload kind EmbeddingであることをLLM generationと区別できる 必要resourceとprotocolが異なる
protocol version 未知versionをfail closedで拒否できる安定識別子 暗黙互換を避ける

4. Embedding空間の互換性

動的host選択は、任意のEmbeddingモデル選択を意味しない。ContextStillのknowledge indexでは、 以下を完全一致させる。1項目でも一致しないhostは候補から除外する。

  • 384次元
  • 固定したmodel IDとrevision／artifact digest
  • query: とpassage: のprefix policy
  • L2 normalization
  • tokenization、truncation、最大入力長の互換contract

受入上の注意: 現行の一部/v1/embeddings実装は入力を常に queryとして処理するため、OpenAI互換のresponse shapeだけでは不十分です。 ナレッジ保存にはpassageを明示できる必要があります。

将来モデルを変更する場合は、動的host切替ではなく、全vector再構築、dual-read、切替、rollbackを伴う 別migrationとして扱う。

5. 希望するlifecycle

ContextStillにEmbedding due workあり
  |
  +-- LARM service activity / capacity確認
        |
        +-- unavailable / active / draining ---- retry hintを返し、claimしない
        |
        +-- compatible host ready
              +-- Embedding lease作成
              +-- ready poll
              +-- provider claim
              +-- ContextStillがspace identityを再検証
              +-- /embed相当をqueryまたはpassage指定で実行
              +-- 次job前にactivityを再確認
              +-- renewまたはDELETE
  • activity snapshotを予約とみなさず、lease作成時に最終admissionを行う。
  • 同じhost上のLLM generation、Embedding、他service workloadをactivityへ反映する。
  • 実行中requestはactivity変化だけで中断しない。
  • due workがなければContextStillはactivityをpollせず、leaseを保持しない。
  • release失敗時もcredentialをlocalで破棄し、TTLをremote cleanupの最終防壁にする。

6. Security要件

  • credentialは短期かつEmbedding endpointとaudienceへ拘束する。
  • claimされたorigin外へのredirectを許可しない。
  • token、完全なclaim response、入力本文、vectorを通常logへ出さない。
  • response body size、vector要素数、数値有限性を制限する。
  • Connection ID、host identity、model revision、dimension、latency、statusはsecretなしで観測可能にする。
  • 既存のLARM API認証方式を利用し、ContextStill専用の長期secretを新設しない。

7. Availability要件

  • compatible hostが0件の場合は明示的なunavailableとretry hintを返す。
  • 停止hostをinventoryから除外し、別のcompatible hostへ新規claimできる。
  • 同一requestを自動で複数hostへ二重実行しない。
  • 429、5xx、timeout時はleaseを破棄・再取得できる。
  • host復帰時、既存のterminal job再作成なしでContextStillが処理を再開できる。

8. 相互受入canary

  1. LARM inventoryでEmbedding対応hostを2台以上、または1台と明示的なunavailable状態を確認する。
  2. ContextStill hostからactivity、lease create、ready、claimを実行する。
  3. queryとpassageを各1件実行し、384次元、有限値、L2 normを確認する。
  4. model ID、revision、prefix policyがclaim広告と一致することを確認する。
  5. 1台をunavailableにし、未開始jobが別hostへ切り替わるか安全に待機することを確認する。
  6. 不一致modelを広告するfake hostが選択されないことを確認する。
  7. leaseを解放し、active connectionとcredentialが残らないことを確認する。
  8. ContextStillのfinalize canary 1件でknowledge、FTS、vector、queue完了を確認する。
  9. 既存のLLM Agent Connection、NightWorkers、SAAA workloadに回帰がないことを確認する。

9. 返却してほしい証跡

  • 配備した完全なGit commit IDとrelease identity
  • 追加・拡張したcontract名とversion
  • Embedding host inventoryのsecretを除いたmodel ID、revision、dimension、prefix policy
  • activity、create、ready、claim、renew、DELETEのHTTP statusと時刻
  • query／passage canaryのdimension、有限値判定、norm、latency
  • host停止・切替canaryの結果
  • claim token、入力本文、vectorをlogへ残していないこと
  • 既存LLM workloadへの回帰試験結果

10. Non-goals／禁止事項

  • LARMへContextStill専用endpointを追加しない。
  • ContextStillのDB schema、公開MCP API、認証方式を変更しない。
  • 同じ384次元という理由だけで異なるEmbeddingモデルを混在させない。
  • query／passageの区別をclientまたはserverの暗黙既定値へ委ねない。
  • 利用不能時に別model、cloud API、固定loopbackへ暗黙fallbackしない。
  • claim token、長期Bearer、入力本文、vectorをlogまたは設定へ保存しない。
  • Embedding host停止をSAAAや他serviceへのcallbackで通知する設計にしない。

11. 完了条件

  • EmbeddingがLARMの動的host対象としてinventory、admission、lease、claim、releaseされる。
  • ContextStillが互換spaceを検証してquery／passage Embeddingを実行できる。
  • host停止時に安全に待機または互換hostへ切り替わる。
  • ContextStill finalize canaryがvectorを含めて登録成功する。
  • 既存のLLM Agent Connectionと他service優先制御に回帰がない。
  • 必要なlive配備手順、rollback手順、secretを除いた証跡が返却される。
