# 秘密値の保存と移行

設定画面から保存するAPIキーは、macOSでは常駐プロセスと同じ利用者のKeychainへ保存します。DBには世代付き参照を保存します。Keychainを利用できないLinux・Windowsでは、秘密値のDB保存は失敗します。環境変数で設定する構成は引き続き利用できます。

Keychainがロック中、アクセス拒否、参照先なしの場合は設定・providerの読出しが失敗します。参照が存在する状態で別の環境変数へ自動的に切り替えません。設定をclearした場合も無効状態を保存するため、再起動で環境変数の古い値が復活することはありません。すでに送信中のリクエストは取消されません。環境変数へ明示的に戻す場合は設定画面の「Use environment」を選んで保存します。画面を読み込めない場合は `bun run src/cli/migrate-secrets.ts --use-environment openaiApiKey` を使えます。削除待ちの旧世代は移行コマンド再実行で回収します。

## 既存DBの移行

同じ利用者で常駐プロセスを起動して、まず対象キー名だけを確認します。

```sh
bun run secrets:migrate:dry-run
bun run secrets:migrate:write
```

移行はキー単位です。新しい秘密値の保存と読出しが成功してから、DB参照を切り替えます。同時更新があれば古い世代の更新は失敗します。途中で失敗した場合は原因を解消して同じコマンドを再実行してください。移行済みのキーは再保存せず、削除待ちの世代を回収します。複数キーの保存は一括transactionではないため、失敗時には一部が更新済みの場合があります。画面を再読込して状態を確認してください。

移行前の値は、旧backup、SQLiteの空き領域、WAL、OS snapshotに残る可能性があります。移行後に旧キーを失効・再発行し、保守停止中に必要なbackupを別の安全な場所へ退避してからDBを再生成してください。稼働中のWriterを迂回してVACUUMやファイル置換を実行しないでください。SSDや複製済みファイルの完全消去は保証しません。

## バックアップと復元

移行済みDBから作るbackupには秘密値を同梱しません。旧形式のbackupを復元した場合は再移行が必要です。別端末、または異なるDBパスへ復元した場合は秘密値を再入力してください。同一DBパスへの復元でもKeychainの対応世代が利用できることを確認してください。clear・更新で破棄した世代を古いbackupから復活させることはできません。

復旧には秘密参照を読める版を使ってください。旧版へ戻して平文形式へ再保存する手順はサポートしません。自動起動するdaemonの利用者を変更した場合も秘密値を再入力します。

実機受入検証は `bun run verify:secrets` です。隔離DBと合成秘密値だけを使い、macOS Keychainへテスト項目を作成・削除します。通常利用者のDB移行は自動実行しません。
