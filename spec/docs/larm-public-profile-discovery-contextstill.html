ContextStillのAgent Connection provide契約

Rust resident lifecycleはjob境界でGET /v3/agent-profiles?profile=contextStillを事前検証に使う。discoveryなしの直接POSTも可能である。service activityがactiveの場合も作成要求を送り、LARMのprovide判定を受ける。

応答はcontractVersion=agent-connection.v3、requestedProfile=contextStill、activityと同じcatalogRevision、一件のprofilesを必須とする。Profileはdeprecated=false、selectionPolicy=explicit-only、id=canonicalProfileで、Providerはllm一件、protocol=openai.chat-completions.v1、endpoint=/v1/chat/completions、非空modelを必須とする。serviceは空であること。

POST /v1/agent-connectionsへprofile=contextStill、audience=same-host、client=contextstill、ttlSeconds=300、allowFallback=false、deploymentPolicy=existing-onlyを送る。Prefer: wait=300とjobごとのIdempotency-Keyを付け、discoveryを行ったときだけexpectedCatalogRevisionを送る。旧入力agentProfileとexplicitAgentProfileは送らない。旧設定のagentProfileは読み込み時に除去し、audienceとTTLを新契約へ移行する。

201ではreadyとllmのclaimableを確認し、202ではLocationが同じConnectionを指すことを確認して期限付きでpollする。responseの公開profile、解決後agentProfile、llm一件のprotocol、endpoint、modelを検証する。claim後のcredential、baseUrl、modelを実行targetに使い、create responseとの不一致時は推論しない。claim credentialがConnectionより先に失効する場合はcredentialの期限を実行targetの期限とし、1回の推論とcleanupに必要な残存時間がなければ開始しない。409 provider_conflictは対象jobをrejectedで終了し、Retry-Afterを記録する。次のjobは新しいIdempotency-Keyで評価する。資源の優先順位はLARMに委ねる。tokenはログ、DB、設定応答、成果へ保存しない。

2026年9月25日の隔離E2Eでは、実LARMへSSHトンネルで接続し、finding candidate queue一件のprovide、claim、実推論、成果一件の保存、次tickでのrelease、active lease 0件を確認した。先に制御APIだけを19810番へ転送した試行では、claimが返した127.0.0.1:9810の実推論先へ届かずprovider_unreachableになった。9810番を同じ接続先へ転送して再実行すると完走した。隔離daemonを使う決定的テストでも同じqueue経路が完了する。

同日のSAAA提供中に実LARMが409 provider_conflictを返すことも確認した。隔離queue jobはfailed、last_outcome_kindはrejected、rejected eventは一件、成果とactive leaseは0件となり、次tickでも再実行しなかった。
