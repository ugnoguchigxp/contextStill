Project identity必須条件の見直し

Project identityはKnowledge自体の成立要件ではなく、repo-scoped Knowledgeを安全に隔離するための要件である。 knowledge_items と検索処理は、scope=global かつidentity列がNULLのKnowledgeを正式に扱う。 調査時点でglobal Knowledgeは29件あり、いずれもidentity列がNULLで、finalize由来だった。

現行Rust finalizeは保存時の scope を常に repo に固定しているため、 identityが無い候補を PROJECT_IDENTITY_REQUIRED でfail-closedにしている。 この拒否はrepository間の情報混入を防ぐ目的では妥当だが、global Knowledgeまで拒否する必要はない。

2026-09-09に採用したcontractは次のとおり。

  • canonical project identityを持つ候補は、従来どおり scope=repo として保存する。
  • identityを持たない候補でも、Evidenceが knowledge_ready で既存の品質・applicability gateを通過した場合は、scope=global、identity列NULLとして保存する。
  • applies_to.general はfacet上の一般適用性でありrepository scopeとは別概念なので、global保存の必須条件にはしない。
  • 保存したscopeと判定根拠をmetadataの storageScope と scopeDecision に保存する。

この変更は既存schemaと検索contractの範囲で実装し、DB migrationは行わない。 global Knowledgeはidentity無しのcompileでも検索可能で、identity付きcompileでもrepo一致Knowledgeとともに検索対象になる。
